# CASE-0016｜数据字典

## 文件说明
- 文件：基础数据集.csv
- 当前记录：22条可辨识的主轴/外围卡片日期标签。
- 该表是**图面标签转录清单**，不是已经核实的格罗皮乌斯完整生平年表。
- event_title、event_description 暂留空：当前图像分辨率不足以准确转录小字号说明，不以常识补写。
- 日期标签保留图面原始形式；特别是末端“1967.7.5”存在读数不确定性，应对照高清原图核验。

| 字段 | 类型 | 单位 | 含义 |
|---|---|---|---|
| event_id | string | — | 当前日期节点记录 ID |
| date_label_original | string | — | 图面可辨的日期原文 |
| start_year | integer | 年 | 日期标签对应的年份数字；仅用于索引 |
| end_year | integer | 年 | 区间结束年；本表暂未填 |
| date_precision | string | — | day/year/day_uncertain 等日期精度标记 |
| timeline_order | integer | — | 按图面环形主轴和外围卡片推定的顺序编号 |
| visual_location | string | — | 日期在画面中的位置 |
| record_kind | string | — | main_axis 主轴节点；callout 外围卡片；两者兼具时注明 |
| event_title | string | — | 事件标题，待高清图转录 |
| event_description | string | — | 事件说明，待高清图转录 |
| verification_status | string | — | 当前核验状态 |

## 数据结构建议
正式研究数据库宜拆分为 events、locations、works、people 四张表：
- events：一行一个人物经历/历史事件。
- locations：一行一个地点，并保留地名原文和标准化地名。
- works：一行一个建筑或设计作品。
- people：一行一个人物及其关系说明。

用 event_id、location_id、work_id、person_id 建立关联，避免把同一事件的地点、人物和作品信息重复写入多个字段。

## 质量规则
1. 日期原文与标准化日期分开保存。
2. 未辨认清楚的数字不得静默纠正。
3. 一张外围图片只有在确认对应事件后才填写 work_id。
4. 地图圆点、人物头像不擅自解释为数量或关系强度。
5. 环形节点角度/间距不自动视为真实时间比例。
