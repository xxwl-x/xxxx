# CASE-0019｜Casino Infographic Isometric：A—E 五维分析

## 0. 类型判断与证据边界

**主表现类型：16｜三维型信息图形（3D Infographics）。** 画面以一台大型老虎机/赌场机器的等轴测立体形态为主体，并把它垂直拆解为多个带有赌场活动场景的模块。

**五大基础逻辑主归属：层级型。** 画面把机器作为整体，将不同赌场活动和设施组织成上下堆叠的模块，每个模块又包含人物、桌台、游戏设备等子对象，形成整体—部件—活动单元的结构。该判断描述图面的组织关系，不意味着赌场业务本身存在真实管理等级。

**辅助标签：09｜层级表现型。** 用于标注整体—部分的结构表达。

图面包含“POKER HALL 6”“ROULETTE HALL”“SLOT MACHINE”等可辨认文字；部分其他文字为占位文本（LOREM IPSUM），不能作为真实内容来源。画面没有可核实的运营数据、客流、收入、赔率或场地尺寸。

## A｜基本数据逻辑

### 1. 最小信息单元
最小单元可以定义为一个赌场功能模块，模块内再拆分具体游戏设施或活动场景。画面可见：
- 顶部老虎机装置及“Slot Machine”标识；
- 上部绿色平台上的桌面游戏场景，旁有“Poker Hall 6”文字；
- 中部橙色平台上的桌面游戏活动；
- 下部红色平台/空间，表现赌场内部活动，并有“Slot Machine”标注；
- 右侧独立轮盘、筹码/奖池类小型三维图形；
- 人物作为场景尺度和活动示意。

注意：图面模块的具体业务含义并非每一层都标注完整。不能只凭颜色或人物动作擅自把未标注层定义为某种特定游戏。

### 2. 关系结构
核心结构为：
- Casino machine（整体视觉容器）；
- Module（垂直功能模块）；
- Activity / equipment（模块内的游戏活动或设施）；
- Person / prop（参与者和辅助道具）。

这是一种空间化的整体—部分结构。画面将赌场业务活动“装配”进老虎机外壳，形成概念隐喻；不应把老虎机内部结构误认为真实赌场建筑剖面或真实设备结构图。

## B｜统计图形与计算方式

本图没有统计图表主模块：
- 没有可辨识的数值坐标轴、刻度、数据表或比例图例；
- 右侧轮盘和筹码图形是具象场景/游戏符号，未显示可核实的概率或金额映射；
- 人物数量和桌台数量服务于场景构建，不构成统计样本。

主要借用的图形方式：
1. **等轴测插画**：同时展示各模块的顶面与侧面；
2. **爆炸式垂直分解**：把整体机器拆成独立模块，突出结构顺序；
3. **场景化微缩插画**：以人物、桌台、设备提示每个模块的用途；
4. **引线与文字标注**：将模块名称和局部说明绑定到主体。

如未来加入真实统计数据，可另设游戏类型、投注额、参与人数、空间面积等统计图表，但这不属于原图内容。

## C｜视觉编码

| 视觉元素 | 图面作用 | 设计分析 |
|---|---|---|
| 体／三维体块 | 机器外壳、分层模块 | 通过厚度、侧面和投影强化模块的实体感 |
| 面 | 各层平台顶面 | 绿色、橙色、红色等不同色面区分不同场景层 |
| 线 | 模块轮廓、外壳边界、引线 | 几何边界清楚，外部引线连接说明文字 |
| 点／小图符 | 人物、筹码、游戏道具 | 人物提供活动语境与尺度，不代表真实人数 |
| 色彩 | 区分模块与赌场品牌氛围 | 粉色背景与高饱和模块色形成强对比；颜色不是数值变量 |
| 透视 | 显示每层的顶面、正面和侧面 | 等轴测视角保持各模块可辨，适合拆解说明 |
| 文字 | 模块命名、局部注释 | 标题和侧边标签引导识别；Lorem ipsum属于占位文字，应在正式作品中替换 |

### 编码风险
- 爆炸图的层间距离为视觉分离，不代表真实设备内部间距；
- 模块体积和颜色不代表收入、客流、概率或价值；
- 人物插画数量不等于参与人数；
- 右侧轮盘与筹码图形未给出图例，不能推断赔率或中奖概率；
- 占位文案不能当作事实。

## D｜数据／信息架构

### 建议的可重建数据表
一行一个功能模块：
system_id, module_id, vertical_order, module_label, activity_type, equipment_type, module_color, annotation_status

模块内对象表：
object_id, module_id, object_type, role, count_visible, count_semantics

其中 count_visible 只可记录图面可见插画对象数，count_semantics 必须明确标记“视觉场景数量，非真实统计人数”。

### Excel结构建议
- Sheet 1 Modules：每行一个垂直模块；
- Sheet 2 Activities：每行一个可辨识活动/游戏类型；
- Sheet 3 Objects：每行一个模块内对象；
- Sheet 4 Annotations：每行一个图面文字标签，标记真实文字或占位文本。

当前 CSV 只保留字段模板。图面未提供模块完整名称、业务数据、金额和概率，空值不得补零。

## E｜视觉叙事架构

阅读路径主要沿垂直方向：
1. 左上角标题先声明“Casino Infographic Isometric”；
2. 从顶部老虎机外壳与 Slot Machine 标识进入；
3. 向下逐层观察赌场桌游和活动空间；
4. 通过左侧 Poker Hall、右侧 Roulette Hall、下方 Slot Machine 等标签识别局部功能；
5. 最后回到机器整体，理解“赌场娱乐项目被装配进一台老虎机”的概念隐喻；
6. 右侧轮盘/筹码小图作为独立的辅助视觉模块，补充赌场语义。

叙事方式是“整体隐喻—分层拆解—局部活动识别—整体回看”。粉色背景弱化真实场景，强化概念海报/商业插画气质。

## 可复用设计方法

1. 选择一个能容纳主题内容的整体物件作为视觉隐喻；
2. 将主题内容按真实或概念上的模块拆分，建立清楚的整体—部分结构；
3. 使用统一等轴测角度，所有模块共享透视方向；
4. 垂直拉开模块间距，避免部件轮廓重叠；
5. 每层用独立色面建立辨识，但必须有明确语义，不将颜色误用为数值；
6. 用人物和道具展示活动情境，同时避免将插画数量误当成统计数据；
7. 侧边文字用折线引导到对应模块，避免引线交叉；
8. 清除占位文字，检查模块名称、场景、引线是否一一对应。

## 分类核验结论
- 主表现标签：16｜三维型；
- 辅助表现标签：09｜层级表现型；
- 五大基础逻辑主归属：层级型（整体—部分结构）；
- 不是统计图表型：没有数据轴、统计刻度或数值编码；
- 不是流程图型：没有明确的步骤、方向性操作或过程状态转换；
- 不是解剖型：虽然使用爆炸分解方式，但其目的在于展示赌场活动模块，不是解释设备内部机械结构。
