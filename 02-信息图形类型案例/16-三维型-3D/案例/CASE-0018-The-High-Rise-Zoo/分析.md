# CASE-0018｜The High-Rise Zoo：A—E 五维分析

## 0. 类型判断与证据边界

**主表现类型：16｜三维型信息图形（3D Infographics）。** 画面采用轴测/等轴测的建筑剖解表达，把一栋高层建筑分解为上下堆叠的生态与使用楼层。三维空间不是装饰背景，而是组织信息的主要手段。

**五大基础逻辑主归属：层级型。** 建筑整体被拆为不同高度的功能层，每层再容纳栖息环境、动物群落、植被或人类活动等子单元，形成“建筑整体—楼层/生态层—局部对象”的包含关系。垂直位置承担层级阅读作用。这里的“层级”是空间功能层级，不代表图中有经过量化的生态等级或优劣排名。

**辅助标签：09｜层级表现型。** 作为交叉检索标签。主表现标签仍是16｜三维型。

证据仅来自用户上传的低分辨率图面和可辨认英文标注。没有可见的真实建筑平面、结构计算、物种清单或工程数据；不能将概念方案当作已建成项目，也不能推断真实承载能力。

## A｜基本数据逻辑

### 1. 最小信息单元
最小记录可定义为“一个垂直功能层”或“一个层内的生态/使用单元”。从画面可辨认的层次包括：
- 顶部：夜行物种相关的屋顶/暗环境区域；
- 水体层：海洋、珊瑚礁与森林水下环境；
- 绿色开放层：植被、陆生动物及相关栖息空间；
- 林地/岩石等栖息层：鸟类与其他动物群落；
- 林冠/步道层：树木、鸟类与游客活动；
- 底部建筑公共层：餐饮及建筑入口/服务空间。

以上是按图面构成归纳的功能分层，不代表完整楼层表或准确楼层编号。

### 2. 关系结构
核心关系为：
- 建筑整体包含多个垂直功能层；
- 每个功能层包含一种或多种栖息环境、植被、动物或人类活动；
- 水、植被、动物与游览设施在不同层之间可能存在生态/运营联系，但图面并未提供完整的物质流或能量流数据。

可抽象为树状结构：building_id → level_id → habitat/program_id → entity_id。若要表达跨层连接，应另设关系表，不应把所有关系硬塞进父子层级。

## B｜统计图形与计算方式

这张图不是统计图表主导型作品。未见坐标轴、数量刻度、比例尺、统计分布或可读取的数值图例。

主要借用的是：
1. **轴测建筑图/等轴测图**：保持多个立面可见，展示建筑层间关系；
2. **爆炸式分层/剖解图**：通过垂直间隔把连续建筑拆成独立层，方便识别每层功能；
3. **空间分区示意**：用不同生态场景区分水域、林地、屋顶等环境；
4. **引线注释**：将文字说明绑定到具体楼层或局部场景。

本图没有足够证据支持任何统计计算。若后续制作数据化版本，可统计各功能层面积、栖息地类型数量、物种数量、公共空间占比等，但这些是可扩展指标，不是原图已表达的数据。

## C｜视觉编码

| 视觉元素 | 图面作用 | 设计分析 |
|---|---|---|
| 体／三维体块 | 建筑楼层、平台与空间容器 | 通过轴测透视展示体块前后、上下关系 |
| 面 | 楼板、屋顶、水面、地面和生态分区 | 不同材质/颜色帮助区分环境属性 |
| 线 | 建筑边缘、支撑构件、引线 | 结构线较克制，注释引线定位明确 |
| 点／小图符 | 动物、人物、树木等对象 | 以具象小比例图形表达空间使用者和生态内容 |
| 色彩 | 区分生态环境和功能层 | 蓝色对应水体，绿色对应植被，灰色/黑色对应结构或岩体；色彩首先承担语义区分 |
| 透视与高度 | 表达层与层的垂直位置 | 垂直排列强化分层关系；不可把视觉间距误读为真实层高 |
| 文字与引线 | 解释栖息地和功能 | 文字置于画面两侧，避免遮盖主体；引线把说明定位到具体层 |

### 编码风险
- 轴测图具有空间真实感，但不等于精确工程模型；
- 楼层间距可能为可读性而夸张，不能据此测量真实高度；
- 动植物小图符主要用于说明场景，不表示精确种群数量；
- 颜色代表环境类别，不应误读为生态质量或数量大小。

## D｜数据／信息架构

### 建议的可重建数据表
一行一个功能层，字段可包括：
building_id, level_id, level_order, level_name, habitat_type, primary_program, visual_color, note, evidence_status

第二张关联表一行一个层内对象：
entity_id, level_id, entity_type, species_or_activity, role, evidence_status

第三张关系表（如需要）：
relation_id, source_level_id, target_level_id, relation_type, description

目前这些字段是根据图面结构提出的重建模型，不是作者原始数据库。CSV 只提供空字段模板，不填入无法核实的楼层面积、物种数量或楼层高度。

### Excel结构建议
- Sheet 1 Levels：每行一个垂直功能层；
- Sheet 2 Entities：每行一个动物/植物/人类活动对象；
- Sheet 3 Cross-level relations：每行一个跨层联系；
- Sheet 4 Annotations：每行一个图面注释及其锚点。

## E｜视觉叙事架构

阅读路径由上向下，跟随建筑垂直结构：
1. 先读标题，理解“高层动物园/狭小空间容纳动物群落”的主题；
2. 从屋顶和顶部生态环境进入；
3. 沿着水体层、绿地层、栖息层逐层向下；
4. 观察每层动物、植被与设施的组合；
5. 最后落到餐饮及建筑公共空间，理解人类活动与生态空间的共存设想。

叙事策略是“整体建筑先建立—分层逐步解释—局部生态场景补充”。文字说明分布于左右两侧，形成图像与注释的交替阅读。

## 可复用设计方法

1. 先明确建筑整体与功能层级，确定每层承载的唯一主功能；
2. 以统一轴测角度绘制建筑体块，保持楼层边界和垂直轴一致；
3. 将楼板/平台适度拉开，形成可辨识的爆炸分层，但标明非比例示意；
4. 每层使用有语义的环境材质和色彩，不要仅为装饰而随机配色；
5. 以少量人物、动物、植被图符表现使用场景，避免把图符数量伪装成统计数量；
6. 使用引线连接说明与对应楼层，检查引线是否交叉或指错；
7. 最后核对：楼层顺序、功能归属、文字锚点、透视一致性、图面事实与推断是否分开。

## 分类核验结论
- 主表现标签：16｜三维型；
- 辅助表现标签：09｜层级表现型；
- 五大基础逻辑主归属：层级型；
- 不是时间轴型：上下顺序表示空间分层，不表示时间先后；
- 不是地图型：图中没有地理位置、区域或真实空间网络数据；
- 不是解剖型：虽然采用分层剖解式展示，但对象是建筑生态方案，不是生物或机械内部结构的解剖说明。
