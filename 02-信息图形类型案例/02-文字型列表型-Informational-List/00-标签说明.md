# 文字型／列表型信息图形 · Informational / List Infographics
**市场化表现形式标签：Informational / List**｜版本 V1.0（2026-11-19）

> “文字型”“列表型”描述的是**内容载体与排版方式**，不是新的基础信息图形类型。任何实例仍须在五大组织逻辑中确定一个主归属，不能因为文字占比高就脱离类型学。

## 概念
通过**标题、分组、编号、短句、图标、信息卡片及阅读引导**，将概念、方法、知识、清单或说明转化为可快速扫描的信息图形。可不包含统计数字，仍有严格的信息组织规则。清单数量多、排得齐，不自动等于数据逻辑清晰。

## 五大基础类型映射

| 五大基础归属 | 主导组织规则 | 文字/列表型常见应用（示例结构） |
|---|---|---|
| [编年型](../../01-信息图形数据逻辑/01-编年型信息图形概念定义.md) | 步骤具有先后依赖，变化顺序不可任意打乱 | “完成任务的 5 个步骤”及逐步解释 |
| [层级型](../../01-信息图形数据逻辑/02-层级型信息图形概念定义.md) | 上位/下位、主次、等级关系 | 多级目录、职责树、优先级清单 |
| [编目型](../../01-信息图形数据逻辑/03-编目型信息图形概念定义.md) | 类别归属与主题分组 | 按用途整理的工具清单、主题知识库 |
| [字母表型](../../01-信息图形数据逻辑/04-字母表型信息图形概念定义.md) | A–Z、拼音或规范索引排序 | 字母术语索引、词汇说明表 |
| [地理图型](../../01-信息图形数据逻辑/05-地理图形信息图形概念定义.md) | 地区位置或空间关系主导 | 地理分区清单、空间位置导览 |

注意：**数字“1、2、3”可以只是编号，不必然代表时间或优先等级**。要从数据的关系而不是页面形式判别。

## A｜基本数据逻辑
最小记录为“条目 ID＋可检验的组织键＋标题＋正文”。组织键为五大主类的相应字段：如编年型 `order_key`、层级型 `parent_id` 或 `rank`、编目型 `category_id`、字母表型 `sort_key`、地理图型 `location_id`。同一外形的列表可以具有完全不同的底层逻辑。

## B｜借用的统计图形与计算
- 完全可以无统计：编号、缩进、分组、索引、交叉引用属于信息结构操作。
- 存在量化指标时可附少量条形比较、进度条、点阵、百分比；比例必须有分母，进度条须有明确总量与当前值。
- 章节编号仅是定位码，**不等于测量的数值变量**；“TOP 5”只有给出真实评定标准才算排名统计。

## C｜视觉编码
| 通道 | 语义 | 优化方法 |
|---|---|---|
| 点 | 列表条目、项目符号 | 同一级条目一致；重点项可有限强调 |
| 线 | 分隔、缩进、路径 | 仅为分隔的线不要画成单向进程箭头 |
| 面 | 卡片、栏目、分组 | 留白优先保证扫描速度；不是越多色块越好 |
| 体 | 对象插画或装饰场景 | 让位于阅读，不产生虚构数据体量 |
| 符号 | 分类、动作、释义 | 统一图标体系，并与文字同义互补 |
| 色彩 | 层级区别、类别区别、强调 | 不同语义不应无规则共用同色 |
| 字体／文字 | 标题/小标题/正文/注释 | 信息层级显著、句式平行、关键词前置 |

文字图形的核心视觉编码是**字体层级、邻近、对齐、分组与一致性**，不能简单认为“文字多＝缺少视觉设计”。

## D｜数据／信息架构
| item_id | organization_key | title | body | icon | source |
|---|---|---|---|---|---|
| I01 | K01 | 条目甲 | 简明解释 | 图符甲 | 待补 |
| I02 | K02 | 条目乙 | 简明解释 | 图符乙 | 待补 |

这是抽象字段示意；其中 organization_key **必须在实际案例里展开为五类之一的具体规则**，不能模糊保存为一个不解释的“排序字段”。内容分层：主题→组织规则→板块标题→条目解释→注释来源。

## E｜视觉叙事架构
三种常见阅读经验：**顺序阅读**（真实步骤）、**层层展开**（结构说明）、**跳读查找**（分类/索引）。是哪种，取决于五大基础逻辑，不由视觉模板决定。一般页面中可采用“主标题→总体观点→模块条目→核心总结”，但不得以标题模板覆盖真实的关系逻辑。

## 应用边界与案例
- 同一数据按类别组织是编目型；按拼音导航是字母表型；按等级划分是层级型；**不会仅因都用竖排列而同属一个基础类型**。
- 使用清单时应检查每条长度、语法平行、单元信息量和跨行一致性，避免装饰压倒检索效率。

## CASE-0013｜文字分类、人物介绍与作品条目

[Los Cuatro Genios — The Beatles｜完整 A—E 分析](./案例/CASE-0013-Los-Cuatro-Genios-The-Beatles/分析.md)

本案例说明文字型／列表型可以通过中央拼接肖像建立主题识别，而主要信息仍由四位人物介绍、并列模块与底部作品列表组织；局部饼图、条形图、年份事件是补充证据，不改变编目型主数据逻辑。可提炼出：同级人物简介使用重复的姓名—符号—段落语法；密集清单使用行对齐、交替浅色条带提高扫描效率；主题插画与版式纹理应服务于文本导航。这些是单案例观察，不应推广成所有文字型作品必须具有中央肖像。

## CASE-0014｜长篇报刊文字分栏与概念插画

[New York Times Sunday Opinion｜完整 A—E 分析](./案例/CASE-0014-New-York-Times-Sunday-Opinion-Winding-Path/分析.md)

这个案例的主信息单位是独立文章，采用报纸窄栏、标题与署名、连续正文和插入式概念插画。中央大面积黑色区域与蜿蜒白线是视觉隐喻和阅读引导，并无统计图表意义；不应因为它像路径就称为时间轴。

## CASE-0013 与 CASE-0014 的比较归纳（阶段性）

| 方面 | CASE-0013：Beatles | CASE-0014：Sunday Opinion |
|---|---|---|
| 子表现 | 图文百科、列表 | 长篇社论、报刊分栏 |
| 最小信息单元 | 人物、作品等知识条目 | 独立文章 |
| 主视觉 | 黑白拼接人物肖像 | 黑白抽象概念图与负空间路径 |
| 文本 | 短介绍、密集表格 | 长段落、细窄多栏 |
| 统计图 | 局部饼图和横条图 | 没有可辨认统计图表 |
| 阅读 | 跨模块自由查找 | 页面级选择文章、文章内部顺序阅读 |

**新增阶段性原则（两个案例共同支持）：**
1. “文字型／列表型”不局限于带编号的清单，亦可包含以多篇文章为独立单元的文字编辑页。
2. 文字是核心信息载体，主题肖像或概念插画可以作为视觉重心，但不必承担定量编码。
3. 页面级信息跳读与内容内部顺序阅读是两种不同层次，应分别分析。
4. 图文比例和统计图有无不是主分类的充分条件；应判断文字条目及其分组是否主导信息组织。
5. 密集列表与长篇分栏分别需要不同的阅读优化：列表强调行对齐、条带与检索；长文强调栏宽、段落节奏、标题区分与连续阅读。

**研究边界**：本案例属于编辑版面的文字型信息设计，不应把每个常规报纸版面都自动定义为统计信息图形；此分类是按项目既定的广义文字型／列表型表现形式归档。
