# CASE-0011｜A world of tastes

## 1. 基本信息与证据边界
- 标题：A world of tastes；中文工作译名：美食的世界
- 发布媒体：South China Morning Post；图面日期：2018-12-22；作者：Marco Hernandez
- 主题：世界各国代表性菜肴及其食材、地域信息。
- SCMP 原始作品介绍说明，作品选取各国国菜；若没有正式国菜，则选取与该地相关、广为人知的流行菜肴。该说明支持“国家/地区—代表性菜肴”的条目关系。
- 本分析依据用户提供的双页图像及 SCMP 原始作品介绍。图中菜名、国家名和底部统计数字字号较小，无法可靠完整转录；未确认的具体条目和数值不录入 CSV。
- 原图为第三方出版作品；本次保存分析、空白字段模板和来源说明，不上传原图二进制。

## 2. 类型归属
- **五大基础逻辑主归属：字母表型（Alphabetical）。** 主体由一组国家/地区条目构成，每个条目配属一道代表性菜肴；图面按国家名称的字母顺序组织为目录，字母键承担定位与检索作用。它不是因为标题以“A”开头而成为字母表型，而是因为条目的排序键为国家名称。
- **辅助逻辑：地理图型。** 底部世界地图提供国家/地区的空间定位与分布背景。
- **辅助逻辑：编目型。** 菜肴、国家和食材构成对象及属性集合，但类别归属不是全图的主要导航规则。
- **表现标签：01 混合型 Mixed Charts。** 菜肴插画目录、顶部说明性示意、底部食材统计和世界地图共同组成一张信息图。
- **辅助表现标签：02 文字型/列表型 Informational / List。** 大量统一单元构成图解式列表，便于逐项浏览。
- 字母表型判断的关键证据是国家名称作为规范化索引键及其排序规则。原图低分辨率下具体标签无法逐项可靠辨认，因此此处确认结构性判断，但不声称已逐条验证所有国家名的精确 A—Z 顺序。

## A｜基本数据逻辑
最小记录单位为一个国家/地区条目，而不是单独一张菜肴插画。

核心关系：
国家/地区条目 → 规范化国家名称排序键 → 代表性菜肴 → 食材属性 → 地理位置

字段维度：
1. 条目 ID：每个国家/地区唯一标识。
2. 国家/地区显示名称：图面显示名称。
3. 规范化排序键：用于字母顺序排列的国家/地区名称。
4. 代表性菜肴名称：该国家/地区对应的菜肴。
5. 菜肴插画：用于视觉识别，不代表数量。
6. 主要食材：可关联多种食材。
7. 地理位置：国家/地区代码或地图定位信息。

主导关系是“索引键—条目—释义/对象”。若将条目顺序打乱，按国家名查找的效率会下降，但国家与菜肴的事实关系不变，这符合字母表型定义。菜肴按主题归类属于内容属性，不取代国家名称的索引顺序。

## B｜统计图形与计算方式
本图不是单一统计图，而是目录与统计模块混合：
- **菜肴插画矩阵**：大量统一规格的圆形单元展示各国代表性菜肴。它承担目录条目和视觉识别功能，不应把插画大小理解为菜肴受欢迎程度或国家数量。
- **顶部环形/关系示意**：解释食材或相关概念之间的关系；具体变量和数值需高清图例确认，不擅自赋予统计含义。
- **底部食材统计模块**：对主要食材或食材类别作比较/分布呈现。需根据图例读取变量、单位、分母和百分比口径；当前图片不足以完整转录。
- **底部世界地图**：用地图标记呈现国家/地区空间位置；地图标记的数量或密度不能在未确认图例时直接解释为真实发生率。
- **右下密度/区域说明**：作为空间信息补充；其统计单位与计算口径需高清图核验。

统计计算原则：
1. 若统计各食材出现频次，应明确“出现一次”的定义及多食材菜肴是否多重计数。
2. 若计算食材占比，应说明分母是全部菜肴、全部食材记录还是某个国家子集。
3. 若比较各区域条目数量，应明确地区划分和每个国家是否只计一次。
4. 字母序号或列表位置仅用于检索，不等于排名、权重或数量。

## C｜视觉编码
| 通道 | 图面应用 | 作用与限制 |
|---|---|---|
| 点 | 每道菜的独立圆形单元；地图定位点 | 菜肴单元是条目定位；地图点才承担空间位置 |
| 线 | 圆形边界、局部引导线、地图边界 | 边界帮助分隔条目，不代表流程或因果 |
| 面 | 圆形菜肴展示区、底部统计区块、地图区域 | 面积不应被误读为菜肴数量 |
| 体/形态 | 菜肴的写实/手绘食物插画 | 以食物形态帮助识别菜品，不编码定量值 |
| 符号 | 食材符号、地图标记、装饰性色块 | 须结合图例判断其类别或统计含义 |
| 色彩 | 红、黄、绿等食物本色与红黄边饰 | 主要增强食物识别、单元区分和视觉节奏 |
| 文字 | 国家/地区名、菜肴名、食材注释、统计标签 | 国家名是关键索引键；应保证可读和顺序可检索 |

视觉优化要点：国家名称与菜肴插画应保持稳定的一对一邻近关系；同规格圆形单元建立目录节奏；底部统计和地图与主体目录在版面上分区，避免读者将目录顺序误认为地图路线或统计排名。

## D｜数据／信息架构
建议使用分离的数据表，避免把国家、菜肴、食材和统计聚合混为一体。

### 表 1：国家/地区索引表
一行代表一个国家/地区条目。字段：entry_id、country_name_as_shown、normalized_sort_key、region_code、map_location_id、source_note。

### 表 2：代表性菜肴表
一行代表一道菜。字段：dish_id、entry_id、dish_name_as_shown、dish_description、illustration_id、source_note。

### 表 3：食材关联表
一行代表一道菜与一种食材之间的关系。字段：dish_id、ingredient_id、ingredient_name、ingredient_role。一道菜可对应多种食材，一种食材也可关联多道菜，因此使用多对多关联表。

### 表 4：食材统计表
一行代表一个统计维度/食材类别的聚合结果。字段：ingredient_id、count_value、denominator、share_value、unit、calculation_method、source_note。当前不得将模糊的图面百分比填入字段。

### 信息展示层级
主题标题与导语 → 国家字母索引条目矩阵 → 单条目中的国家名与代表性菜肴 → 顶部食材/关系说明 → 底部食材统计 → 世界地图空间定位与密度说明。

## E｜视觉叙事架构
1. 标题“A world of tastes”提出全球饮食文化主题。
2. 导语说明选取各国国菜或代表性流行菜肴的规则。
3. 主体以统一规格的菜肴插画组成大型条目矩阵，国家名称承担字母索引，读者可以逐项浏览和查找。
4. 顶部小型图示解释食材或相关概念，提供阅读辅助。
5. 底部食材统计把单道菜的属性提升为整体层面的共性观察。
6. 世界地图将目录条目重新放回地理空间，补充各国分布语境。

这是“字母索引式全球菜肴目录＋统计与地理补充”的叙事。主阅读任务是浏览/查找条目，地图和统计负责扩展理解，而非取代索引结构。

## 可复用设计方法
1. **字母索引＋图像目录**：用规范名称排序，让读者能检索，同时以对象插画快速识别。
2. **固定单元矩阵**：统一图像单元的尺寸、边界和文字位置，建立大规模目录的阅读节奏。
3. **条目与属性分离**：国家/地区作为索引条目，菜肴作为对应对象，食材作为关联属性。
4. **目录与统计分层**：主体目录回答“有哪些”，底部统计回答“整体有什么共性”。
5. **空间补充而非空间主导**：地图提供地点参照，但只要索引顺序仍是主要导航，主逻辑仍是字母表型。
6. **统计口径透明**：多食材、多国家条目须说明计数单位和分母，避免重复计数造成比例误读。
