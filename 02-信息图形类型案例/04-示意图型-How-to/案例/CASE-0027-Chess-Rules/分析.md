# CASE-0027｜Chess Rules（A—E 五维分析）

## 0. 类型判断

**主表现标签：04 示意图型。** 作品用棋盘格、棋子模型、方向箭头和分步骤画面解释国际象棋规则，重点是“如何移动、如何吃子、如何理解特殊走法”。

**五大基础逻辑主归属：编目型。** 图中将 King、Queen、Rook、Bishop、Knight、Pawn 六种棋子作为分类对象，并为每种对象配置移动方式和规则属性。其主体是“棋子类别—规则属性”的目录式结构。开局和特殊走法是关联的规则示例。

**辅助表现：** 06 比较型（挑战者与卫冕冠军对照、数据数字栏）；02 文字型/列表型（棋子说明、规则文字）。棋盘不是地理地图：格子表示棋局状态空间，棋子位置是规则演示状态，不代表真实地理坐标。

## A｜基本数据逻辑

### 1. 最小记录单元
主体最小记录单元是“棋子类型—移动规则”：
- piece_id：棋子类型；
- piece_name：棋子名称；
- movement_rule：移动方式；
- capture_rule：吃子方式；
- special_rule：特殊规则；
- illustration_id：对应的图解；
- note：文字说明。

特殊走法另按 rule_id、rule_name、precondition、action_sequence、result 记录。棋局事实数据（冠军、年份、比赛数字）应独立于规则目录。

### 2. 数据结构本质
这是一个以棋子类别为行、规则属性为列的编目矩阵：
- King、Queen、Rook、Bishop、Knight、Pawn；
- 每个类别关联移动方向、步数/范围、是否可跳跃、吃子方式等属性。

棋盘图解不是地理空间数据，而是有限格网中的状态与动作示意。若需结构化图解，可用 board_state、from_square、to_square、move_type 表示一次合法移动示例。

## B｜统计图形与计算方式

本图以规则示意为主，不以统计图表为主：
1. **棋子说明图标：** 每种棋子配名称、价值/作用描述；
2. **棋盘格移动图：** 用箭头表示移动方向与可达格；
3. **序列化特殊规则：** 通过编号步骤展示王车易位、吃过路兵等过程；
4. **开局阵型：** 通过初始棋盘状态说明开局；
5. **数字事实栏：** 记录棋史、赛事和比赛数据，属于辅助事实模块，不是主规则示意。

没有从图形面积或箭头长度计算统计量的必要。若将“棋子价值”进行数字化，应注明其是规则教材常用相对价值还是某一引擎评估分，不能混为一谈。

## C｜视觉编码

| 通道 | 图面作用 | 观察 |
|---|---|---|
| 棋盘格 | 提供离散的规则演示空间 | 黑白格形成稳定坐标参照 |
| 棋子图符 | 区分六种棋子 | 以轮廓/造型快速识别类别 |
| 箭头 | 标示合法移动方向、吃子路径 | 多色箭头区分移动、吃子、移动并吃子等动作 |
| 编号圆点 | 表示特殊规则的操作步骤 | 让多步动作可按顺序阅读 |
| 红/黑/白 | 区分双方棋子并建立版面主色 | 红黑几何底色形成强烈视觉识别 |
| 文字标签 | 解释规则名称、条件与限制 | 为图形示例补充规则边界 |
| 人像照片 | 连接2024世界冠军赛背景 | 属于新闻/赛事语境，不承担棋规数据编码 |

**设计优点：** 把抽象文字规则转换为棋盘上的动作示范；用多种箭头颜色区分动作类型；特殊走法用编号步骤拆解。

**优化建议：** 每种箭头颜色都应在图例中固定对应一种动作；棋盘图示应保持棋盘方向与坐标一致；对规则限制补充文字条件；图示中的局面应标明轮到哪一方行动。

## D｜数据／信息架构

建议拆为：

**Pieces：** piece_id、piece_name、side_color、relative_value（如有来源）、description。

**MovementRules：** rule_id、piece_id、movement_pattern、range、jump_allowed、capture_pattern、special_condition。

**RuleExamples：** example_id、rule_id、board_state、from_square、to_square、move_sequence、result。

**SpecialMoves：** special_move_id、name、preconditions、steps、resulting_state。

**TournamentFacts：** fact_id、event_name、year、person_or_team、value、unit、source_note。

**ChampionshipMatchup：** player_id、player_name、role（challenger/defending champion）、country。

把规则、棋局示例和赛事新闻数据分开，避免将赛事背景误读成棋规本身。

## E｜视觉叙事架构

1. 顶部标题“Chess rules”及2024世界冠军赛说明建立主题；
2. 左侧棋子目录先解释王、后、车、象、马、兵各自的功能；
3. 中央区域用棋盘和多色箭头解释基本移动；
4. 右上通过编号图解说明王车易位和吃过路兵等特殊走法；
5. 中部下方展示开局阵型与开局说明；
6. 数字栏补充棋史和赛事事实；
7. 底部以挑战者与卫冕冠军肖像、对战记录和比赛信息收束。

阅读逻辑为“认识棋子→理解移动→学习特殊规则→了解开局→补充棋史与赛事背景”。

## 可复用方法与边界

- 抽象规则应转化为具体状态、动作和结果；
- 棋子类别适合用目录结构组织，动作规则适合用图解呈现；
- 不同箭头颜色必须有清楚、稳定的图例；
- 特殊规则需要明确前置条件，不能只画动作结果；
- 棋盘是抽象离散空间，不应因为有格网和位置就归为地理地图；
- 赛事数字、人物对照属于背景信息，不能取代主规则叙事。

## 归档结论

主表现标签为04示意图型；辅助表现为06比较型、02文字型/列表型；五大基础逻辑主归属为编目型（棋子类别—规则属性）。本图不属于地理地图型。
