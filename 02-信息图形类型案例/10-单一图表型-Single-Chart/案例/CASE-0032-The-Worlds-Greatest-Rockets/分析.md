# CASE-0032｜The World's Greatest Rockets: Past, Present, and Future：A—E分析

## 0 类型判断
**主表现：10 单一图表型。** 一整幅页面以相同的纵向方向展示大量黑白/灰度火箭与运载器的外形，按多行排布，并配名称、长度或规格短标签。全图的主要定量依据是载具之间的相对高度，未像典型混合图形那样增加一个完全独立的统计模块。

**基础数据逻辑：编目型**。每个火箭/飞行器是一个可枚举对象，带名称、系列、尺寸与技术属性等字段。体积/高度顺序属于视觉比较维度，不是“父级支配子级”的组织层级。不同年代（past/present/future）在标题中出现，但图并未使用水平年份时间轴；不属于编年型主图。

## A 基本数据逻辑
最小记录是**一种火箭或飞行器**。关键字段：vehicle_id、vehicle_name、vehicle_family、launch_vehicle_type、length_m、diameter_m、height_definition、status_as_of_2015、source、verification_status。具体有效载荷和推力若原图未明示，就不应擅自增加成可视数据。

图面可见标签包含 You (scale reference)、Apollo LM Ascent、Morpheus、V2 Rocket、DC-X、Mercury-Redstone、Juno 1、Vanguard、Black Arrow、The Able、Shavit、Falcon 1、Star-1、Sputnik、Space Shuttle、Saturn V、N1、Energia、Long March、SLS等。并非所有对象都来自同一年代、同一种用途；比较前必须先统一测量定义。

## B 统计图形与计算
采用**等比例轮廓图（to-scale silhouette comparison / pictorial bar chart）**：所有对象直立摆放、以各行共同基线比较尺寸；较小者在上，巨大火箭集中在下面，形成从小到大的分层阅读。大部分单体无抽象条形，而以真实形体代替矩形条。图面顶部标注截至2015年2月，不能据此推断各项已建成/投入运营。

比例逻辑：若原始长度L_i以统一比例尺s显示，图示高度h_i=s×L_i；与标准条形图同样使用长度编码。若无法确认全行跨行使用同一比例尺，应谨慎，不能仅凭图片像素计算火箭实际长度。形体宽度、推进器数量、颜色深浅和体积都没有独立数量图例，不要误认为推力或载重指标。

## C 视觉编码
| 通道 | 作用及信息语义 |
|---|---|
| 轮廓高度 | 表现火箭尺寸/长度对照 |
| 对齐基线 | 建立可比较的视觉参照；逐行基线清晰 |
| 黑灰渐变/阴影 | 呈现火箭形状、结构辨识；并非数值颜色尺 |
| 分行 | 容纳大量对象并形成尺度范围的视觉节奏 |
| 白色留白 | 隔离相邻对象，降低信息拥挤 |
| 文字 | 单体名称与小字号尺寸/属性标签 |
| 人物比例参照 | 左上“You”提供近身尺度感，不应被当作火箭类别 |
| 标题 | Past, Present, and Future 提供历史范围，但没有严格年份序列编码 |

当阅读跨行比例时，需检查作者是否实际采用统一比例；不同宽度火箭彼此不可直接以轮廓面积计算容积。

## D 数据／信息架构
建议：
- Vehicles：vehicle_id、vehicle_name、vehicle_family、length_m、diameter_m、date_or_era、status_as_of_2015、measure_definition、source。
- Groups：group_id、group_label、sort_rule、row_number。
- VisualScale：chart_id、scale_m_per_unit、baseline_type、is_same_scale_across_rows。
- References：source_id、original_document、publication_date、citation.
CSV当前仅登记图面明显可辨的对象名称，全部真实数值字段均需用原图高清标签或可靠原始数据填充。未核实的发射器功能类别、任务、年代及状态保持空白。

## E 视觉叙事架构
1. 大字号标题“ROCKETS”直接建立主题。
2. 第一行小型飞行器与人物参照引入尺度概念。
3. 读者由上至下浏览多行渐大的载具，逐步比较长度与形态。
4. 中下部呈现越来越大的运载火箭和航天飞机，增强规模感。
5. 最底部巨大火箭并列形成尺寸对照的视觉高潮，突出超大运载器之间的差异。

其强项是让人“直观看到尺寸”，而不是通过大量数字表格理解尺寸等级。它是统一图形语法下的密集对象比较，**不是根据年代先后排序的时间轴**。

## 可复用方法与边界
- 单体形态稳定、便于辨识且具有可比较的长度指标时，可采用等比例轮廓阵列。
- 统一比例尺、对象高度定义、基线是可信比较的前提。
- 可用分行解决数量多、尺寸跨度大的布局，但必须提示是否跨行同尺度。
- 用人物/常见物作为尺度参照，可降低抽象数字的理解难度。
- 名称、尺寸和类别应建立结构化数据，而不仅留在图片注释中。
- 阶梯式从小到大属于尺寸比较排序，不应误判为管理等级或编年序列。
