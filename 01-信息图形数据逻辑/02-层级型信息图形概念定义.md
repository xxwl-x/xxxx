# 02｜层级型信息图形：概念定义

## 定义
以主次、上下位、包含、从属或等级差异组织信息，使读者理解整体与部分、父级与子级、不同等级之间的关系。单纯大小不同或排版缩进，并不足以证明存在层级。

## A｜基本数据逻辑
层级型常见两种结构：结构层级以父节点与子节点形成树状或嵌套关系；等级层级依据同一评价标准形成高低、优先级或等级次序，不一定存在父子关系。关键问题是“谁属于谁”或“谁高于谁”，而不是“谁先发生”或“谁与谁并列”。并列分类优先判断为编目型。

## B｜统计图形与计算方式
结构表达可用树图、组织结构图、旭日图、矩形树图、冰柱图和放射树；等级表达可用排序条形图、点图和等级矩阵。可计算层数/深度、子节点数、叶节点数、节点权重和同级份额。只有子类互斥、穷尽且可加时，父级汇总值才可由子级相加。树形连线本身不等于统计聚类结果。

## C｜视觉编码
| 通道 | 主要作用 | 编码注意 |
|---|---|---|
| 点 | 层级节点、角色 | 节点位置应反映真实层次 |
| 线 | 父子、上下位关系 | 减少交叉，连线语义明确 |
| 面 | 嵌套区域、分支、权重 | 面积映射数量时按面积比例 |
| 体 | 分层或空间结构 | 透视会影响面积判断，谨慎使用 |
| 符号 | 分支类型、职责 | 图标不应自行暗示等级 |
| 色彩 | 分支或层深 | 类别色与等级明度序列区分 |
| 文字 | 节点名称、等级、数值 | 字号、缩进、位置与真实层级一致 |

优先级：层级关系 → 分支结构 → 同级比较 → 装饰。

## D｜数据/信息架构
树结构建议一行一个节点，字段包括 node_id、parent_id、label、depth、value。等级型另设 item_id、rank、rank_basis；不要为了视觉树形而伪造父节点。检查孤立节点、循环引用、重复计数和汇总口径。字段示例不代表真实案例数据。

## E｜视觉叙事架构
结构型：整体总览 → 展开一级分支 → 深入子级 → 回看整体结构。等级型：说明评价标准 → 呈现等级分布 → 聚焦关键差异 → 解释判断结果。叙事必须交代层级判定依据。

## 分类核验
如果去掉视觉上的大小差异后，父子/等级关系仍可由数据字段或规则说明，则层级判断更可靠。
