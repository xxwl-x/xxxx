# 04｜字母表型信息图形：概念定义

## 定义
以名称、字母、拼音、笔画或其他标准化索引键进行约定排序，帮助读者快速定位和检索条目。其核心是检索规则，不表示重要程度、时间顺序或因果关系。

## A｜基本数据逻辑
每个条目具有稳定 ID、显示名称和规范化排序键。索引键决定条目进入哪个分组/字母桶及其排列位置。同名不同对象应通过唯一 ID 区分；别名应链接到规范条目。中文索引可使用拼音、笔画等方式，但必须声明排序规则并一致执行。按主题类别组织的清单属于编目型；按重要程度排列属于层级型。

## B｜统计图形与计算方式
核心处理包括文本标准化、排序、去重、分桶、匹配和交叉引用。有真实数据时可统计各索引桶条目数、首字母频次和检索覆盖率。可借用字母索引网格、分组列表、点阵矩阵和频次条形图。排序序号仅表示检索位置，不等于权重或价值。

## C｜视觉编码
| 通道 | 主要作用 | 编码注意 |
|---|---|---|
| 点 | 词条/条目定位 | 同级条目保持统一 |
| 线 | 索引连接、跳转 | 表示查找路径，不表示因果 |
| 面 | 字母桶、索引分区 | 网格稳定，面积不暗示数量 |
| 体 | 条目对象辅助示意 | 不应干扰索引检索 |
| 符号 | 类别提示、导航 | 不替代规范检索键 |
| 色彩 | 字母段、分组导航 | 色彩不能打乱既定排序 |
| 文字 | 索引键、条目名、释义 | 检索键突出，支持快速扫描 |

优先级：索引键 → 分桶导航 → 条目标题 → 释义和交叉链接。

## D｜数据/信息架构
建议一行一个词条，分开存储 item_id、display_name、normalized_key、bucket、definition。排序键应由公开、可复核的归一化规则生成；别名链接到规范条目，不重复制造实体。字段示例不代表真实案例数据。

## E｜视觉叙事架构
以用户主动检索为主：确定目标名称 → 识别索引键 → 定位分桶 → 阅读条目 → 跳转相关信息。推荐阅读路线不能替代索引本身的排序逻辑。

## 分类核验
如果改变名称索引顺序会影响查找效率，但不会改变对象间的事实关系，则字母表型判断较合理。
