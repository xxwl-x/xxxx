# 01｜编年型信息图形：概念定义

## 定义
以具有明确先后关系的序列组织信息，使读者理解事件、阶段、步骤或状态如何推进。时间是常见排序依据，但编年型的本质是顺序关系，不只是画面上出现时间轴。

## A｜基本数据逻辑
- 核心单元：事件、阶段、步骤或状态节点。
- 核心关系：节点之间存在可说明的先后、前驱、后继或阶段依赖。
- 抽象模型：序列 S=(N1,N2,…,Nn)，每个节点有稳定 ID 与顺序键；需要时记录前驱节点。
- 判断条件：交换关键节点会破坏原本要表达的进程、过程或步骤约束。
- 边界：仅按日期排序的名录可能只是有序目录；按字母排序属于字母表型；按重要程度排序属于层级型。先后不自动意味着因果。

## B｜统计图形与计算方式
常见表达包括时间轴、阶段带、甘特区间、序列点图、折线图、阶段柱形图和泳道图。可计算阶段时长、节点间隔、相邻差值、累计值和变化率。折线图仅在相邻数值具有连续比较意义时使用；不等距时间不能伪装成等距比例轴。区分发生时间、持续时间、累计量与单阶段数量。

## C｜视觉编码
| 通道 | 主要作用 | 编码注意 |
|---|---|---|
| 点 | 事件或阶段节点 | 顺序清晰，关键节点可突出 |
| 线 | 主序列、前后关系 | 箭头表达方向，避免把装饰线误读为因果 |
| 面 | 阶段区间、时间跨度 | 长度按真实时长比例或声明为示意 |
| 体 | 场景、对象辅助说明 | 体积不应冒充数量 |
| 符号 | 事件类别、动作或结果 | 同一符号语法保持一致 |
| 色彩 | 阶段、轨道、状态 | 类别色与数值色阶分开 |
| 文字 | 时间、节点名、注释 | 日期格式、单位与精度统一 |

优先级：顺序主轴 → 节点关系 → 阶段区分 → 装饰细节。

## D｜数据/信息架构
最小表建议一行一个节点，字段包括 node_id、order_key、label、predecessor_id、start_time、end_time、note。多条并行序列增加 track_id；时间与文字描述分字段存储。字段示例不是实际案例数据。

## E｜视觉叙事架构
起点/背景 → 关键阶段 → 转折/变化 → 结果或当前状态。先让读者看懂主序列，再补充重要节点的解释。并行轨道应共享可读的时间或阶段参照。

## 分类核验
如果调换关键节点会使所表达的过程失真，编年型判断更可靠；若顺序可自由调整，需检查是否其实是分类、索引或等级排序。
