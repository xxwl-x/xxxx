# 03｜编目型信息图形：概念定义

## 定义
以明确的类别、主题或属性归属为基本秩序，将对象分组、列举或横向比较。它回答“有哪些对象、如何分类、各类有什么特点”。本质是可复核的分类规则，而不是简单采用列表版式。

## A｜基本数据逻辑
对象集合 O 与类别集合 C 之间存在归属关系。互斥分类中每个对象在指定口径下只属于一个类别；多标签分类中一个对象可同时属于多个类别，汇总时不能把各类数量简单视为互斥分区。分类依据必须明确，例如功能、材质、主题、用途或来源。类别若存在明显父子包含关系且该关系是作品重点，应考虑层级型。

## B｜统计图形与计算方式
常用统计包括类别频数、构成比例、组内均值/中位数、组间差值和交叉分类。常用图形包括分类条形图、分组柱形图、点阵图、矩阵、小倍数图和百分比堆积图。饼图/环图只适用于总量口径明确的场景。纯名录可以不做数量统计；没有频数数据时不得补造比例。互斥且穷尽的类别构成才可解释为总和 100%。

## C｜视觉编码
| 通道 | 主要作用 | 编码注意 |
|---|---|---|
| 点 | 类别成员、计数单元 | 计数时单元大小一致 |
| 线 | 分组边界、对应关系 | 分隔线不代表流程或因果 |
| 面 | 类别分区、矩阵单元 | 面积只有映射数量时才具定量含义 |
| 体 | 产品或对象示意 | 主要用于识别，不冒充数值 |
| 符号 | 类别标识、对象语义 | 同一类别保持符号一致 |
| 色彩 | 类别身份 | 类别色稳定，不伪装连续数值 |
| 文字 | 类名、成员、归类依据 | 类别标题优先，解释分类标准 |

优先级：分类规则 → 类别边界 → 成员信息 → 类别比较 → 装饰。

## D｜数据/信息架构
对象表建议包含 item_id、item_name、category_id、attribute。多标签分类应将对象表与“对象—类别”关联表分开；记录类别代码、定义、同义词、未分类项和分类版本。字段示例不代表真实案例数据。

## E｜视觉叙事架构
主题提出 → 说明分类标准 → 展示类别全貌 → 展开典型成员 → 横向比较 → 总结差异。读者通常可以跳读，因此类别导航、标题和视觉分组必须清晰。

## 分类核验
如果类别顺序可以自由调整且不改变信息含义，分类逻辑可能成立；若核心是父子归属或先后过程，则分别考虑层级型或编年型。
