# 04｜基础数据集构建

## 核心强制原则
**一行一条最小记录、一列一个原子属性、一个单元格只能有一个值。** 值可以是名义类别、量化数值、日期、坐标分量、单段文本、单一图片资产引用等；不允许一格存多个独立事实。

例：名称+经度+纬度不是放在一个单元格，而是三个字段；GDP值与货币单位分开；名称+GDP也必须占两列。

## 数据类型
- 名义值：名称、ID、类别、地区编码；
- 数量值：整数、浮点数、计数、百分比、货币数值（单位单列）；
- 时间值：ISO日期/年份/时间区间的原子字段；
- 图像数据：单一图片文件的asset_id或URI，图像本体放素材目录；多个图片应另建关联表多行存储；
- 文本文字：一个文本字段内可以有**一个完整文本单元**（如一条引述或摘要），不可用顿号、分号或逗号塞入多个独立类别或指标。

## 特别要求
1. 数据先定义**最小记录粒度**（一行究竟是一个人、地点、事件还是一次观测）。
2. 一列只定义一种数据意义与类型；同列不混入计量单位、注释。
3. 多值关系另建关联表，如一个作品有多个标签，使用works、tags、work_tags而非`tags="A,B,C"`。
4. 缺失值用空字段并在数据字典注明；区分0、未知、不适用。
5. 经纬度分列，经度longitude、纬度latitude，并注明坐标系（如WGS84）。
6. 不将来源和置信度挤在数值单元格中。
7. 原始数据、清洗数据和供视觉设计的数据视图分别保存，保留变换步骤。
8. 对可量化数据记录单位、分母、统计时点、精度和来源；对图片记录授权与素材出处。

## 阶段门槛
数据表可以通过唯一键关联；每个字段有清楚定义；至少完成一次字段原子性和来源核验。
